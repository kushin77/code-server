# SCOPE_BOUNDARIES.txt
# This file defines the boundaries and limits for code-server deployment
# Violations of these boundaries indicate misconfiguration

================================================================================
ALLOWED SCOPE
================================================================================

NAMESPACES:
  ✓ code-server (primary namespace)
  ✓ kube-system (read-only for DNS, system services)
  ✓ ingress-nginx (if external ingress needed - read-only)

CONTAINER PREFIXES:
  ✓ code-server-*
  ✓ code-server_* (for volumes)

LABELS REQUIRED:
  project: code-server
  app.kubernetes.io/name: code-server-enterprise
  app.kubernetes.io/managed-by: terraform-helm

TERRAFORM STATE:
  ✓ Only resources with project: code-server label
  ✓ Only resources in code-server namespace
  ✓ Only code-server service accounts

DOCKER COMPOSE NETWORKS:
  ✓ code-server-enterprise_services
  ✓ code-server-enterprise_database
  ✓ code-server-enterprise_ingress
  ✓ Any network with code-server prefix

DOCKER VOLUMES:
  ✓ code-server_* (all volumes)
  ✓ Any volume with code-server prefix

================================================================================
FORBIDDEN SCOPE - MUST NOT MODIFY
================================================================================

NAMESPACES:
  ✗ default
  ✗ kube-system (except reading DNS services)
  ✗ kube-public
  ✗ kube-node-lease
  ✗ Any non-code-server namespace
  ✗ Other projects' namespaces

CONTAINER PREFIXES:
  ✗ Any container NOT starting with code-server-
  ✗ Containers from other projects
  ✗ System containers (unless code-server-labeled)

RESOURCES IN OTHER NAMESPACES:
  ✗ Modifying Deployments in any namespace except code-server
  ✗ Modifying Services in any namespace except code-server
  ✗ Modifying ConfigMaps in any namespace except code-server
  ✗ Modifying Secrets in any namespace except code-server
  ✗ Modifying PVCs in any namespace except code-server

CLUSTER-WIDE MODIFICATIONS:
  ✗ Creating ClusterRoles not scoped to code-server
  ✗ Modifying StorageClasses
  ✗ Modifying PersistentVolumes (except reading)
  ✗ Modifying Ingress Controllers
  ✗ Modifying ServiceMeshes (can use but not modify)
  ✗ Modifying DNS configurations

DOCKER COMPOSE:
  ✗ Deploying containers without code-server- prefix
  ✗ Modifying existing deployments not owned by code-server
  ✗ Sharing volumes with non-code-server containers
  ✗ Connecting to networks not prefixed with code-server-enterprise_

TERRAFORM STATE:
  ✗ Modifying resources without project: code-server label
  ✗ Accessing other namespaces via terraform
  ✗ Modifying cluster-wide resources
  ✗ Using service accounts from other projects
  ✗ Importing resources not labeled for code-server

RBAC:
  ✗ Using cluster-admin role
  ✗ Creating roles that access other namespaces
  ✗ Sharing service accounts with other projects
  ✗ Granting permissions to modify other namespaces

================================================================================
VALIDATION RULES
================================================================================

EVERY TERRAFORM FILE MUST:
  1. Reference only code-server namespace
  2. Use label selector: project: code-server
  3. Use label selector: app.kubernetes.io/name: code-server-enterprise
  4. NOT modify resources in other namespaces
  5. NOT use cluster-admin or overly permissive roles

EVERY DOCKER-COMPOSE SERVICE MUST:
  1. Have container_name: code-server-<service>
  2. Have labels: project: code-server
  3. Use only code-server- prefixed volumes
  4. Connect only to code-server-enterprise_ networks

EVERY HELM TEMPLATE MUST:
  1. Deploy only to code-server namespace
  2. Include labels: project: code-server
  3. Use serviceAccount: code-server
  4. NOT create cluster-wide resources

EVERY KUBERNETES MANIFEST MUST:
  1. Specify namespace: code-server
  2. Have labels: project: code-server
  3. Reference only code-server service account
  4. NOT modify resources outside code-server namespace

================================================================================
RED FLAGS - IMMEDIATE REVIEW REQUIRED
================================================================================

FILE CONTENT CHECKS:
  🚩 namespace: default (anywhere except kube-system/ingress-nginx)
  🚩 namespace: other-project (any reference to non-code-server namespace)
  🚩 clusterAdmin: true (should be namespace-scoped role)
  🚩 clusterRoleBinding (should use RoleBinding in code-server namespace)
  🚩 container_name: NOT starting with code-server-
  🚩 label: project NOT set to code-server
  🚩 image: from other-project or unknown origin
  🚩 serviceAccount: NOT code-server
  🚩 Delete operations on resources not labeled project: code-server

GIT COMMIT CHECKS:
  🚩 Changes to files outside terraform/environments/private/
  🚩 Changes to files outside helm/code-server-enterprise/
  🚩 Changes to files outside docker-compose-cluster.yml
  🚩 Terraform imports from other namespaces
  🚩 kubectl commands to non-code-server namespaces
  🚩 References to cluster-wide resources

RUNTIME CHECKS:
  🚩 Containers running without code-server- prefix
  🚩 Resources in namespaces other than code-server
  🚩 PVCs mounting volumes not prefixed code-server_
  🚩 Services exposing other projects' containers
  🚩 Network policies allowing cross-namespace traffic
  🚩 RBAC granting access to other namespaces
  🚩 Terraform modifying non-code-server resources
  🚩 Pod logs showing "permission denied" in other namespaces

================================================================================
SCOPE VIOLATION PENALTIES
================================================================================

During Development:
  1st violation: Warning in PR comments
  2nd violation: Block PR merge
  3rd violation: Code review required from platform team

In Production:
  Any violation: Immediate rollback
  Incident: Document root cause
  Prevention: Add pre-commit hook

================================================================================
SCOPE VERIFICATION SCRIPTS
================================================================================

Location: scripts/

  validate-scoping.sh      - Check all configs match scope boundaries
  verify-deployment.sh     - Verify runtime deployment is scoped correctly
  audit-terraform.sh       - Audit terraform for scope violations
  audit-docker.sh          - Audit docker-compose for scope violations
  audit-kubernetes.sh      - Audit kubernetes resources for scope violations
  cleanup-violations.sh    - Remove out-of-scope resources (DANGEROUS)

Run before every deployment:
  ./scripts/validate-scoping.sh
