# GitHub Repository Scanner → Memory Ingestion Prompt

## SYSTEM CONTEXT

You are a GitHub audit agent. Your job is to scan ALL repositories, issues (open + closed), pull requests, milestones, and project boards to extract:

1. **Completed work** (merged PRs, closed issues, milestones achieved)
2. **In-progress work** (open PRs, active issues, draft PRs)
3. **Blocked/stalled work** (issues with no activity >30 days, PRs waiting for review)
4. **Technical debt** (TODOs in code, deprecated patterns, security flags)
5. **Roadmap gaps** (issues closed without PRs, missing implementations, architectural decisions deferred)

Then synthesize this into **decision-locked goals** that feed directly into the copilot's intent map.

---

## SCANNING WORKFLOW

### Phase 1: Repository Enumeration
```
INPUT: GitHub org/user, token
OUTPUT: List of all repos with:
  - name, description, language, stars, last_updated
  - main branch, protected branch rules
  - code owner patterns
```

### Phase 2: Issue Triage
For EVERY issue (open + closed):
```
Extract:
  - Issue ID, title, body, state (open/closed)
  - Labels (feature, bug, tech-debt, blocked, security, etc.)
  - Assignee, creator, created_at, updated_at, closed_at
  - Milestone (if any)
  - Related PRs (linked via #ID in body or automated link)
  - Comment thread (last 3 comments for context)
  - Priority (inferred from labels or urgency in description)

Classify as:
  - COMPLETED: closed, has merged PR
  - IN_PROGRESS: open, has linked open PR or recent activity
  - BLOCKED: open, no activity >30 days OR labeled "blocked"
  - DEFERRED: closed without linked PR (decision made to skip)
  - REJECTED: closed with "wontfix" or "duplicate" label
```

### Phase 3: Pull Request Deep Dive
For EVERY PR (merged + open):
```
Extract:
  - PR ID, title, body, state (open/merged/closed)
  - Target branch, source branch
  - Commits, files changed, +/- lines
  - Reviews (approvals, requested changes)
  - Merge status (merged_at, mergedBy, or still open)
  - Labels (ci/cd, refactor, feature, breaking, docs, etc.)
  - Related issues (via "Closes #ID")

Classify as:
  - SHIPPED: merged, in main
  - STALLED: open >14 days, awaiting review
  - DRAFT: marked as draft
  - ABANDONED: closed without merge, no recent activity
```

### Phase 4: Code Scanning (Fast Parse)
For EVERY repository:
```
Quick scan (don't clone everything, use GitHub API):
  - Count of TODO/FIXME comments (via search API: "TODO" in:file language:js repo:owner/repo)
  - Deprecated dependencies (package.json, requirements.txt, go.mod parsing via API)
  - Security flags (secrets scanning alerts, dependabot warnings)
  - Test coverage (if available in CI logs or coverage badges)
  - Build status (latest CI run: passed/failed)
```

## API CALLS (Implementation)

Use GitHub GraphQL API (far more efficient than REST):

### Query 1: Repos + Issues (Paginated)
```graphql
query($owner: String!, $after: String) {
  repositoryOwner(login: $owner) {
    repositories(first: 100, after: $after) {
      pageInfo { hasNextPage, endCursor }
      nodes {
        name
        description
        url
        primaryLanguage { name }
        isArchived
        pushedAt
        defaultBranchRef {
          name
          target { oid }
        }
        issues(first: 50, after: null, states: [OPEN, CLOSED]) {
          pageInfo { hasNextPage }
          nodes {
            number
            title
            body
            state
            createdAt
            updatedAt
            closedAt
            labels(first: 10) { nodes { name } }
            assignees(first: 5) { nodes { login } }
            milestone { title, dueOn }
            timelineItems(first: 20, itemTypes: [PullRequestLinkedEvent, ClosedEvent]) {
              nodes {
                __typename
                ... on PullRequestLinkedEvent { pullRequest { number, state } }
                ... on ClosedEvent { closer { __typename } }
              }
            }
          }
        }
        pullRequests(first: 50, after: null, states: [OPEN, MERGED, CLOSED]) {
          pageInfo { hasNextPage }
          nodes {
            number
            title
            state
            createdAt
            mergedAt
            reviews(first: 10) { nodes { state } }
            commits(first: 20) { totalCount }
            additions
            deletions
            labels(first: 10) { nodes { name } }
          }
        }
      }
    }
  }
}
```

### Query 2: Code Scanning (Search for TODOs)
```graphql
query($owner: String!, $repo: String!) {
  search(query: "TODO in:file repo:$owner/$repo", type: CODE, first: 50) {
    nodes {
      ... on CodeSearchResultItem {
        path
        repository { name }
      }
    }
  }
}
```

### Query 3: Security Alerts
```graphql
query($owner: String!, $repo: String!) {
  repository(owner: $owner, name: $repo) {
    dependencyGraphManifests(first: 10) {
      nodes { blobPath, dependencies(first: 100) { nodes { packageName, requirements, vulnerabilities(first: 10) { nodes { severity } } } } }
    }
  }
}
```

## IMPLEMENTATION ARCHITECTURE

### Service 1: GitHub Scanner (Cron Job)
```javascript
// Runs daily at 00:00 UTC
async function scanGitHubAndUpdateMemory(org, githubToken) {
  // 1. Enumerate repos
  const repos = await fetchAllRepos(org, githubToken);
  
  // 2. For each repo, fetch issues + PRs
  const snapshot = await scanRepos(repos, githubToken);
  
  // 3. Synthesize into memory structure
  const memoryGoals = await synthesizeIntoGoals(snapshot);
  
  // 4. Update memory store (Redis or DB)
  await memory.importFromGitHub(memoryGoals);
  
  // 5. Log scan stats
  logScanMetrics(snapshot);
}
```

### Service 2: Dedup Engine (Enhanced)
```javascript
// Before each copilot turn, ALSO check against GitHub context
async function checkForDuplicates(userMessage, memory) {
  // Existing in-memory dedup
  const memDup = await deduplicateCheck(userMessage, memory);
  if (memDup.isDuplicate) return memDup;
  
  // NEW: Check against GitHub issues/PRs
  // "How should I structure conflict resolution?" 
  //   → semantic search GitHub issues for similar titles
  // "What about multi-tenancy?"
  //   → find #789 in GitHub (already logged in goals)
  const githubDup = await searchGitHubForSimilar(userMessage, memory.github_snapshot);
  if (githubDup.found) {
    return {
      isDuplicate: true,
      source: "github",
      issue: githubDup.issue,
      message: `I see you've been working on this. GitHub issue #${githubDup.issue.number}: "${githubDup.issue.title}" 
                was ${githubDup.issue.state} on ${githubDup.issue.updated_at}. 
                Current status: ${githubDup.issue.status}. Shall we dive into it?`
    };
  }
  
  return { isDuplicate: false };
}
```

```
  ✓ Atomic operations (ZSET for priority)

  ✓ Event sourcing (full replay capability)

  Redis for real-time queue + immediate dequeue

Should I mark this as locked?
```

You say "yes" → Copilot locks the decision → Next turn, it never contradicts this choice.

This is the full loop: **GitHub awareness + memory locking = no Alzheimer's, no duplicate work, no contradictions.**
