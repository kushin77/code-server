## What Happens on Each Turn (User Experience)

```
USER: "How should I structure the conflict resolver?"

↓ (Copilot receives message)

1. Dedup check: Is this similar to prior suggestions?
   ✗ No → Continue
   ✓ Yes → Flag & ask for permission to expand

2. Memory context injected:
   - Active goals: [GitPeak #789, ElevatedIQ #456, ...]
   - Locked decisions: ["Use Redis for queue", "Helm for deployment"]
   - Blockers: ["ECS migration pending", "API rate limits"]
   - Assumptions: ["All repos on GitHub", "Issue labels follow convention"]

3. Claude Sonnet 4 called with enriched system prompt:
   - System prompt includes entire memory context
   - Claude responds with GitHub-aware, decision-respecting advice

4. Response recorded in memory:
   - Suggestion ID created: sug_1698765432_xyz
   - Embedding computed (for future dedup)
   - Timestamp, domain, text stored
   - Conversation history updated

5. User accepts suggestion:
   → Decision automatically locked
   → Future advice respects this lock
   → Goal status updated

RESULT: Copilot now knows this decision. Next turn, it will never contradict it.
```

## Key Features (Solving Your Problem)

### ✅ Never Repeats Suggestions
- Semantic similarity check (0.85 threshold)
- Flags duplicates with prior timestamp
- Asks permission to expand instead of repeating

### ✅ Never Forgets Decisions
- Intent map locks decisions once accepted
- Future advice explicitly aligns with locked choices
- Asks permission to revisit locked decisions

### ✅ Surfaces Contradictions
- Before offering conflicting advice, copilot surfaces conflict
- Shows prior decision + new suggestion side-by-side
- Asks user to choose direction

### ✅ GitHub-Aware
- Daily scan of all repos/issues/PRs
- Technical debt tracked (TODOs, deprecated, security)
- Blockers mapped (issue #X blocks 3 other repos)
- Cross-repo dependencies visible

### ✅ Multi-User, Shareable
- Package as Code Server extension
- Distribute via Marketplace, GitHub, Docker
- Users install in 4 steps
- Team members can share memory (Redis/PostgreSQL backend)
