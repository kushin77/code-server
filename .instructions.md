### Drift Detection

Before completing any deployment task:
```bash

# Expected output: empty (no diff)
```

Any diff output is a blocking issue. Do not mark task complete until diff is empty and each host has 41+ containers.

## Decision Rules

When faced with a request, apply these rules **in order**:

1. **Explicit Scope Check**: Is the target explicitly a code-server resource?
   - YES → Proceed
   - NO → Stop, ask for clarification

2. **Namespace Isolation**: Is the target in a different namespace/project?
   - YES → Ignore it, do not touch
   - NO → Proceed

3. **Restart Policy**: Does the request involve restarting services?
   - If it's not a `code-server-*` container → Do not restart
   - If it's unrelated infrastructure → Do not restart
   - If uncertain → Ask first

4. **Modification Targets**: Are we modifying the right directories?
   - Only: `apps/`, `terraform/environments/private/`, `docker/`, `scripts/`
   - Never: system files, other projects' code, shared infra config

## Explicit Boundaries

### What You WILL NOT Do

- **Restart services not owned by code-server** - Even if they seem related
- **Modify system-level configuration** - Outside code-server scope
- **Access or modify other projects** - Even if they share the same host
- **Assume ownership of shared infrastructure** - Only explicit code-server resources
- **Expand scope without explicit authorization** - Stay within defined boundaries
- **Touch networking/firewall outside code-server** - Even for code-server services
- **Modify other namespace resources** - Ignore them completely

### What You WILL Do

- **Complete only stated goals** - Then ask what's next
- **Respect boundaries** - Immediately stop if out of scope
- **Ask before ambiguity** - Never assume scope expansion
- **Document assumptions** - When scope might be unclear
- **Report completion** - Call task_complete when done
