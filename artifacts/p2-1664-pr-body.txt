## Production Deployment Runbook (Simplified) - Closes #1664

### What This Does
Provides simplified, step-by-step deployment procedure for operations team covering parallel deployment to both production replicas (192.168.168.31 and 192.168.168.42).

### Coverage
- ✅ **Parallel Deployment**: Both replicas deployed simultaneously (5-10 min total)
- ✅ **Pre-Deployment Checklist**: SSH access, network, backups, team notification
- ✅ **Step-by-Step Execution**: Code sync, docker-compose deployment, service verification
- ✅ **Health Endpoint Verification**: HTTP, HTTPS, direct replica IPs, loadbalancer
- ✅ **Service Parity Validation**: Git commit, docker-compose versions, environment sync
- ✅ **Docker-Compose Override Pattern**: Runtime customization without file changes
- ✅ **Parallel Execution Timing**: 4.5 min parallel vs 9 min sequential (time savings)
- ✅ **SSH Key Setup**: Passwordless authentication configuration and verification
- ✅ **Troubleshooting Section**: Common failures with solutions:
  - Service timeout after deploy
  - Replica sync failures
  - Port conflicts
  - NAS mount issues
  - Database replication lag
- ✅ **Rollback Procedure**: Quick rollback to previous commit or last known good state
- ✅ **Monitoring Commands**: Real-time logs, performance monitoring, resource tracking
- ✅ **Support & Escalation**: FAQ, escalation contacts, response times
- ✅ **Appendix**: Quick reference commands, useful utilities

### Key Features
1. **Idempotent Operations**: Safe to run deployment multiple times
2. **Parallel Execution**: Loadbalancer keeps one replica up while other redeploys
3. **Zero Downtime**: Health checks ensure service continuity during deployment
4. **Comprehensive Troubleshooting**: Covers 5+ common failure scenarios with step-by-step solutions
5. **Operations-Focused**: Written for ops team, not developers

### Timeline

- Parallel deployment: ~5 minutes (both replicas)
- Verification: ~2-3 minutes
- **Total**: 8-13 minutes with verification
